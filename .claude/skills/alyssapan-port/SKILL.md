# AlyssaPan: Clock Tower 3, decompiled and ported to PC

AlyssaPan reconstructs a PS2 game function by function into C that runs on a PC platform layer. It is the
fifth port by the same author: MioPan (Fatal Frame 2, `../MioPan`), ReiPan (Fatal Frame 3, `../ReiPan`),
RosePan (Rule of Rose, `../RosePan`), YamiPan (Forbidden Siren 2, `../YamiPan`), with MikuPan (Fatal Frame
1, `../MikuPan`) upstream of them all. **It keeps YamiPan's priorities and design rules, builds on YamiPan's
C++ Pan layer, and reuses every shim the other Pans have** (the user, 2026-11-09). YamiPan's skill
(`../YamiPan/.claude/skills/yamipan-port/`) is the closest precedent for anything not written here.

**State (2026-11-09): bootstrap.** Repo created (nothing committed yet: the user decides), YamiPan's Pan
layer carried over and trimmed to the generic, the tools carried over and renamed, the references
written; **the build is green** (a run opens the window and reports `main` as its one stub) and
`refresh.py` runs on CT3. The ELF's symtab names 2,621 of 2,628 functions, so naming is mostly done; the
TU map (bootstrap 5) and the siblings' shims (open-items.md "Next up" item 2) are not. The game is Clock Tower 3 (USA,
`SLUS_206.33`, ELF 2003-01-24), annotation tag `CT3`; C compiled by **Metrowerks CodeWarrior** (like FS2),
linked at 0x01810000 with prebuilt GCC SDK / newlib / libgcc objects.

## One TU per session (the protocol, YamiPan's)

Work is cut into translation units: one game object file, rebuilt as one source file under `src/` (key =
its path). Each session takes one TU (or a slice) from claim to commit; everything lives in the repo
(`tools/reverse/data/tus.json`, this skill, git). Invocations: `/alyssapan-port tu <TU>`,
`/alyssapan-port next`.

1. **Claim and read.** `python tus.py claim <TU>` (or `next --claim`), `python tus.py brief <TU>`, read
   `work/tu/<slug>/brief.md` and the staged bundle. The brief's **slice** is the session's work. A **host
   task** (`tus.py queue <key> --top --task TEXT`) skips 2-5.
2. **Boundaries.** Pin the object's extent from the symtab's local-symbol run and the brief's identity
   section: `tus.py define <file> <lo>-<hi> [...] --why "..."` (hi exclusive).
3. **Names.** The symtab's names are exact: never rename them. Only what it left unnamed (a function
   Ghidra split, a literal) gets a name, through a batch (`name_ctx.py`, tag `game-inferred`).
4. **Header first.** `src/<dir>/<file>.h`: structs at the EE offsets with `static_assert`s, globals with
   their address and symtab name, prototypes of what other TUs call, each with `// CT3 0x...`.
5. **Code.** Reconstruct the slice (reconstruction.md): the ROM's semantics, `CT3 0x<addr>` above every
   function, statics as the symtab has them, flags and modes named, draws through the host draw module.
   Delete this TU's stubs elsewhere.
6. **Check.** `python tus.py check <TU> --run 15`: build, stubgen, callcheck, layoutcheck, smoke run.
   **Look at `work/shots/last.png`: the picture is the test.**
7. **Record.** Facts -> architecture.md; traps -> hazards.md "AlyssaPan" (dated); questions and decisions
   -> open-items.md; better ways of working -> this file, reconstruction.md, the tools README.
8. **Finish.** `python tus.py finish <TU> --status done|verify|partial|blocked --summary "..." --notes "..."
   --coauthor "<the session's Co-Authored-By line>"`: builds, records, commits on the work branch
   (`ct3-port`; it refuses `main`). Report in 3-5 lines and **stop**.

## Time limits (the user's rule, from YamiPan, 2026-11-04)

A session has 60 minutes (from `work/run.lock`'s `started`, or the first command); at 45 start nothing
new; at 60 finish whatever is left. **No game run lasts more than 10 minutes**: `build.py --run N` and
`tus.py check --run N` carry their limit; `gdbrun.py` has none, so a background run gets `Monitor` with a
timeout. Every other background command gets a limit too.

## Starting sessions

The user starts each session: `/alyssapan-port next`, or the desktop app's scheduled task
`alyssapan-next-tu` every 20 minutes (since 2026-11-09), whose prompt is `tools/reverse/routine.md`. A
scheduled run passes `py preflight.py` first (stop switch `work/STOP`, run lock `work/run.lock`, clean
tree, the work branch `ct3-port`, Ghidra serving `SLUS_206.33`), does one step -- the next bootstrap step
while open-items.md "Next up" item 0 has one, then one TU or host task -- commits, pushes to origin and
releases the lock. A session never starts other sessions, agents or scheduled tasks, and never edits
`autopilot.py`, `preflight.py` or the routine. Within a session, run the protocol without asking; pause
only for decisions that are the user's -- when no answer can come, decide, record the doubt in
open-items.md, finish. Porting runs at effort `xhigh` (this frontmatter; the user's rule): keep that line.
To stop the runs, create `tools/reverse/work/STOP` (or disable the task in the app).

## The user's rules (open-items.md "Decisions" has the dates and sources)

- **The picture is the test.** Logs, stub hits and callcheck show the code ran, not that it is right.
- **Any aspect ratio is the port's #1 feature**: one renderer-owned source for display size and aspect
  (`DisplayGeometry`), never a fixed 4:3 / 640x448 in host draw code; 2D anchored and scaled from it, 3D
  widened, never stretched.
- **No GS emulator, not even for textures.** Keep the game's draw decisions, replace its output: the
  packet-writing step calls a native host draw module per subsystem; textures are decoded at their source
  (the file record the game reads) straight to GPU textures.
- **Name the patterns**: repeated values, modes, kinds and flag bits become `enum`s / `#define`s /
  `constexpr` as the code is decompiled.
- **The Pan layer is modern OO C++; the game layer stays authentic** (cpp-port.md). CT3's game layer is C.
- **Reuse every sibling shim** (2026-11-09): window handling, input, audio, memory card, saves, menus...
  as classes here; cpp-port.md "To carry over" is the list.
- **Japanese stays Japanese** where Shift-JIS turns up (reconstruction.md "Japanese text").
- **Skip cinematics in smoke runs** (RosePan's rule): a skip switch smoke runs control.
- **Automated work at xhigh or above; sessions never start sessions.** Debug probes are stripped before
  committing.

## Naming conventions (Ghidra)

- `game-symbol`: the symtab's names, exact, never renamed. `lib-match` / `lib-context` for library
  code the symtab left unnamed (none so far); `game-inferred` for what a session names by reading.
- Style: the game's own (C identifiers as the symtab spells them, prefixes `ga`, `ss`, `as`, `Sun`...).
